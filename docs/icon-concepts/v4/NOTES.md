# R 形浪 · v4 位图与矢量探路

> 目标：把 `docs/icon-concepts/v3/raw/A3.png` 推成能读成 R 的「R 形浪」，并验证这种造型在 16/18px 是否成立。
>
> 约束：24×24、`fill="none"`、`stroke="currentColor"`、round cap/join；不改 `lib/client.js`，不重启 dsh。A1 留作备用，不删。

## 1. 位图变体（阶段一）

### 1.1 先试图像编辑，失败

把 A3 作为 `inline_data` 参考图，要求“把浪改成 R”，模型输出读成花体 **e/a**，完全读不出 R。该尝试判失败，图存 `.gen/rejected-a3-edit.png`，不纳入 `raw/`。

### 1.2 改走文字直出

先做一张 A3-7 测试图，明确 R 的解剖：**左竖、上卷闭合碗、右下斜腿**。测试图成功读出 R，随后复制为 A3-1 基线；原图存 `.gen/A3-7-trial.png`。

六个最终变体均为 1024×1024、白底居中、无文字/边框/渐变。每张只调一个变量：

| 文件 | seed | 单一变量 | R 可读性 | 32px | 小尺寸风险 |

## 2. 矢量探路（阶段二）

### 2.1 选型

从 A3-1 / A3-2 的骨架出发，先试了三条路线：

- **B**：外轮廓 R + 波峰顶。160px 能读成 R，但更像普通手写 R，潮汐感不足。
- **C**：A3-1 的斜竖 + 大卷 + 长腿。与 B 接近，24px 以下同样退化成普通 R。
- **D**：在碗内加一条 1.4 宽的细内线，做“内卷浪舌”。160px 像碗里长了一只眼睛；24px 变成一团；16px 让碗读成 `a`/`e`。**否决**：既没增加浪的身份，又损害 R 的可读性。

最终采用 **B2**：在 B 的基础上把斜腿末端向上收一点，形成一个很小的“回浪”尾。

### 2.2 结构

`docs/icon-concepts/v4/explore-vector.svg`

- 24×24 viewBox；根节点 `fill="none"` `stroke="currentColor"` `stroke-width="2.2"` `stroke-linecap="round"` `stroke-linejoin="round"`。
- 主 R：左竖 + 上卷闭合碗，一笔；路径从 `M5.8 20.8` 起，到碗底 `8.4 10.2` 收。
- 斜腿：从 `M10.8 11.3` 起，向右下扫到 `18.8 20.0`，末端再向上收 `C19.5 20.0 20.0 19.7 20.2 19.2`。
- 水滴：两个空心圆，`(19.2,4.6) r=0.5`、`(20.2,6.9) r=0.35`；描边分别 1.1 / 1.0。

### 2.3 尺寸观察

`docs/icon-concepts/v4/explore-preview.png` 给出 16/18/24/48px 的浅底/深底对照。

| 尺寸 | 实际看到什么 | 判断 |
|---:|---|---|
| 160px（设计时看） | R + 回浪尾 + 两颗水滴；像一支带笔锋的手写 R | R 成立；“浪”只是笔势，不是明确符号 |
| 48px | R + 两颗水滴；腿端上卷可见 | R 成立；潮感弱 |
| 24px | R + 一颗水滴；腿端上卷缩成小缺口 | R 成立；第二颗水滴消失 |
| 18px | R + 一个点；腿端已平 | 浪尾消失；仍读 R |
| 16px | R + 一个点（大水滴缩成句点）；腿端回浪与第二颗水滴消失，碗内空腔只剩约 2–3px | **R 成立，浪不成立** |

关键原因：24×24 的 viewBox 放到 16px 时，2.2 的描边只剩 1.47 设备像素；碗内空腔本来就只有约 2–3 个设计单位，缩小后接近闭合，细内线会先糊掉，小水滴会先缩成一个点。R 的骨架能活下来，是因为它由大笔画构成；浪的身份依赖的恰是这些先消失的小结构。

## 3. 结论（阶段三）

**这种纯 stroke 的 R 形浪，适合做 24px 以上的 R-first 标记，不适合做 16px 且要求“同时读出浪”的图标。**

- 16/18px：R 可读，但只剩 R + 一个点；如果用户看到的是“一个带点的 R”，不会联想到潮汐。
- 24px：R + 一颗水滴，勉强有“水”的暗示，但浪尾已经退化。
- 48px+：回浪尾与两颗水滴都在，才接近“R 形浪”的意图。

如果 16px 必须同时读出 R 和浪，有三条替代路线：

1. **分工**：16px 用纯浪符号（A1 路线；当前是位图，需要另行矢量化），24px+ 用 R 形浪。也就是“响应式标记”，不要求一枚图标在所有尺寸讲同一个故事。
2. **拆件**：24px+ 做 R + 独立浪冠的组合标；16px 只保留浪冠。不要让浪冠长在 R 的笔画里。
3. **换表现**：用填充/负空间做浪与 R 的共用轮廓。这能保住 16px，但违反本轮的 `fill="none"` 约束，属于另一轮设计。

不建议继续在 R 的碗里加细线：D 已经证明，24px 以下会先变成“眼睛/blob”，再变成 `a`/`e`。
