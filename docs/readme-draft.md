# 有事，找阿汐
**When in doubt, ask Axi**

阿汐是您的常驻管家：您把事说清楚，她拆成一张张带验收标准的活儿，派给合适的 worker，盯到收尾，再把结果和卡点带回来。她不替 worker 写代码，也不要求您记命令——您只管对她说人话。

## 经典用法

- **「阿汐，让老周把登录页的验证码换成滑块，今天上线。」**
  <sub>她拆好验收条件和步骤，派给老周，盯到联调和测试都过，再回来告诉你。</sub>
- **「阿汐，我们聊聊账单页要不要拆成两个 tab，先别动代码。」**
  <sub>她先和你把取舍、边界和风险过一遍，等你说“就按这个来”，再落成能派的活。</sub>
- **「阿汐，等支付回调联调完，再让小林接后台导出。」**
  <sub>她记住先后顺序，前一件没收尾就不催后一件；轮到小林时把上下文一并交过去。</sub>
- **「阿汐，盯一下数据看板那个活，卡住就告诉我卡在哪。」**
  <sub>她盯着进展，遇到卡点带着原因来问你，而不是等到最后才说“做不完”。</sub>
- **「阿汐，搜索结果页不对，筛选条件没带上，让改的人再返工一版。」**
  <sub>她把问题写成可验收的标准，退回给原来的 worker，改完按同一标准复核。</sub>
- **「阿汐，给写文档的 worker 开一下这个仓库的写权限，只开 docs/。」**
  <sub>她按最小范围调整权限，改完把生效范围和回滚方式一起告诉你。</sub>

## 待确认点

- **英文标题**：暂用「When in doubt, ask Axi」，它和「有事，找阿汐」的语义最贴，也延续品牌偏句子的语气；「Ask Axi」更短、更像产品名/按钮，二选一。
- **Axi 与 Ria**：英文标题把「阿汐」音译成 Axi，但仓库、包名、hero 和现有文档的英文名都是 Ria；是统一成 Ria（Ask Ria），还是保留 Axi 作口号、Ria 作产品名？
- **H1**：草稿用中文标题作 H1，英文标题放下一行，`dsh-ria` 不再出现在页顶；要不要在页脚或安装段保留仓库名，避免 GitHub 仓库名在正文里消失？
- **示例与旧场景**：六条都是虚构但可信的日常（老周/小林、登录页/账单页/看板/搜索页）；是否换成你们真实项目，以及旧「典型场景」里的微信派活、换模型两条要不要并进来？
- **简介收尾**：简介末尾不再放「更多细节见 DESIGN.md 与 docs/」；要不要保留这一句，还是让首屏彻底干净？
